# Console measurement contract

Console shows several different kinds of numbers. They are deliberately named by what they measure; no field called only “context” or “tokens” is authoritative across hosts.

## Plausibility alarms and unavailable data

- A projected LHC view larger than a known model window is an alarm, not a normal “context” value. Console does not currently have a trustworthy cross-host model-window source, so it does not invent this comparison.
- Latest provider input is not the same as active host context. A provider receipt may include host instructions and schemas omitted from the projected LHC view, and it describes the latest completed/reported request rather than necessarily the in-flight one.
- Native-host compaction freshness is host-artifact state. Console must not claim an LHC view is current when a newer native compact is detected. No common cross-host artifact currently exposes this; Codex rollouts do, and broad host support remains unavailable until a bounded adapter exists.
- Token estimates use the thread’s recorded estimator. Provider receipts remain provider numbers and are never replaced with LHC estimates.
